Public-repository workflow supplied by t:
Before implementing each new enhancement or fix, verify the repository's visibility with its hosting service. If it is public, find a matching open issue or create one describing the requested change and acceptance criteria. Record its URL before editing code, reuse it throughout the task, and link the PR to it. An open issue explicitly supplied for the current task already satisfies this requirement; do not create a duplicate. Follow the same rule for additional fixes or enhancements discovered during the session. Keep private context, credentials, and transcripts out of public issues. If visibility or issue creation cannot be verified, resolve that before implementation. This rule does not require issues for private repositories or for read-only investigation. If no task has been supplied yet, wait for the user's task before creating an issue or changing files.
